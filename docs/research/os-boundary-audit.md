## Top 5 — Most Likely to Break on a User's Mac But Pass Tests

| Rank | Boundary | Why it breaks silently |
|------|----------|------------------------|
| 1 | **Keychain `SecItemCopyMatching` with `kSecReturnAttributes` + `kSecMatchLimitAll`** (`EngineSecrets.all`) | macOS file-based Keychain returns `errSecParam (-50)` for this exact query combo; tests use `InMemoryEngineSecrets` which always succeeds. The real bug (errSecParam on bulk read) already bit production once. |
| 2 | **`removexattr("com.apple.quarantine")` on bundled engine copy** (`EngineInstaller.clearQuarantine`) | Quarantine clearing fails silently on some macOS versions / filesystem configs (APFS clones, external drives, network homes); tests don't copy real bundles. A user gets "stalled on first launch" with no test signal. |
| 3 | **`Process.run()` of bundled Python/Postgres** (`ProcessEngineLauncher`, `PostgresSupervisor`) | Child process inherits wrong env, sandbox denies `exec`, `pg_ctl` not in PATH, PostgreSQL version mismatch, `initdb` fails on non-ASCII home paths; tests use in-memory fakes or mock processes. |
| 4 | **`ASWebAuthenticationSession` + loopback listener for Google OAuth** (`GoogleDesktopAuth`, `LoopbackListener`) | System browser may not launch, user denies consent, loopback port taken, PKCE/state mismatch, network error; tests use fake HTTP transports and never exercise the real browser/loopback dance. |
| 5 | **`claude --version` / `claude auth status` subprocess detection** (`ClaudeCodeExecutor.detect`, `_invoke`) | `claude` not in PATH, not signed in, version output format changes, rate-limit messages, CLI not installed; tests use `ExecutorNotInstalled` fake and never run the real binary. |

## Summary

**15 boundaries identified**, 5 critical (ranked top-5), 4 medium, 6 low/not-used.

**Key pattern**: Every boundary that touches the macOS Keychain, filesystem (quarantine, bundle copy), child processes (Python, Postgres, `claude`, `fdesetup`), or system browser (OAuth loopback) has **no integration test that exercises the real thing**. The test suite relies entirely on in-memory fakes (`InMemoryEngineSecrets`, `InMemoryVaultKeyStore`, fake `EngineLaunching`, fake `HTTPTransport`, fake `Executor`). This is by design (tests must be fast, hermetic, no Keychain/network) but creates a blind spot: **macOS-specific failures that only appear on a user's machine**.

**Recommended next steps** (not in scope of this audit):
1. Add macOS CI runner that runs a "smoke" integration test: install real bundle, launch engine, verify control socket handshake, run one MCP call.
2. Add manual QA checklist for the top-5 boundaries (Keychain bulk read, quarantine clear, process launch, OAuth loopback, `claude` CLI).
3. Consider a "real Keychain" test target that runs only on macOS CI (not local dev).
